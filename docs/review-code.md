# Code review: bookmark-ai (2026-10-29)

Scope: `lib/**`, `app/**`, `components/**`, `proxy.ts`, migration, config, CI. Verified by running `npm run verify` (lint, typecheck, 259 tests in 10 files, `next build`: all green), applying `0001_init.sql` to a throwaway Postgres 16 container with an `auth` stub (runs cleanly; `array_to_string` in the generated column is accepted), and hitting `/api/enrich` and `/api/health` on the dev server.

## 1. Score: 7 / 10 as a hiring signal

This reads like a working engineer's codebase, not a scaffold: a real repository boundary with a contract test, a careful SSRF guard (every literal spelling I threw at it was blocked: `169.254.169.254`, `127.1`, `0x7f000001`, `2130706433`, `[::ffff:127.0.0.1]`, `localtest.me` via DNS), Zod at every boundary, `Result` instead of thrown errors, a migration that actually runs, and a README that explains trade-offs honestly. What keeps it from 8+ is a cluster of correctness bugs a reviewer will find within an hour: an open redirect in the auth `next` handling, a rate limiter whose per-user tier is silently never applied and whose key is spoofable, a cloud-mode `reload()` that reverts the UI to the page-load snapshot, enrichment overwriting user edits, a dead "select all" shortcut, and a handful of unused exports and a false comment about CI. None is architectural; all are fixable in a day, and fixing them would move this to a strong 8.

## 2. Findings

### HIGH

**H1. Open redirect through `next`.** `lib/actions/auth.ts:29`, `app/auth/callback/route.ts:9`. The check `startsWith("/") && !startsWith("//")` misses backslashes. `new URL("/\\evil.com", "https://app")` resolves to `https://evil.com/` (verified in Node), and `redirect("/\\evil.com")` is normalised the same way by browsers. Scenario: phishing link `https://app/login?next=/\evil.com`; the victim signs in on the real site and lands on the attacker's. Fix: parse with `new URL(next, origin)` and require `url.origin === origin`, or reject anything matching `/^\/[\\/]/`. Centralise in one `safeNextPath()` used by both files (today the logic is duplicated, with a third copy in the Zod schema at `auth.ts:10`).

**H2. Rate limiter tiers never apply; key is spoofable.** `lib/ratelimit.ts:61-66` caches one `RateLimiter` per name and ignores `options` on every later call, so `app/api/enrich/route.ts:21` gives signed-in users 30/min or 12/min depending on who hit the route first after boot. `clientKey` (`ratelimit.ts:73`) trusts the first `X-Forwarded-For` entry; I sent three spoofed headers from a client that was already at 429 and each got a fresh bucket (400 = passed the limiter). On Vercel the platform overwrites XFF, but the README does not say this is a deployment assumption, and self-hosted it is a full bypass. Fix: key the registry by `name + capacity + windowMs` (or create two named limiters), take the *last* XFF hop or a platform header, and fall back to a shared `unknown` bucket with a lower cap rather than per-header buckets.

**H3. `reload()` in cloud mode restores a stale snapshot.** `lib/repo/remote.ts:28-33,46-48` return the `initial` arrays captured at page load; `listBookmarks()` never refetches. `provider.tsx:463` (`renameTag`) and `:581` (`resetDemo`) call `reload()`, which dispatches `hydrate` with that snapshot. Scenario: signed-in user adds five cards, renames a tag; the five cards vanish from the UI (and the rename is not visible) until a hard refresh. `renameTag` has no UI caller today, so this is latent, but it is a trap in a class whose doc comment says the dashboard code is identical across modes. Fix: either make `RemoteRepository.list*` call a `listBookmarksAction`, or have `reload()` do `router.refresh()` in cloud mode. (Note the whole tag-rename path, provider → `renameTagAction` → `rename_tag` RPC, is unreachable from the UI; either wire it to the sidebar or delete it.)

**H4. Enrichment clobbers concurrent user edits.** `provider.tsx:274-285` writes `title`, `tags`, `imageUrl`, etc. unconditionally when `/api/enrich` returns, up to several seconds after creation. Scenario: user imports a browser export with tags/titles, or renames a card while it is "Reading page…"; the AI response overwrites the title and replaces the user's tags (`e.tags.length ? e.tags : bookmark.tags`). Fix: build the patch from the *current* bookmark (`state.bookmarks.find`) at response time, only fill fields that are still empty/default, and merge tags.

### MEDIUM

**M1. Session refresh lost on proxy redirects.** `proxy.ts:39-45`. Both redirects create a new `NextResponse` without copying the cookies that `setAll` wrote into `response`. The `@supabase/ssr` guide explicitly warns to copy `supabaseResponse.cookies` onto any redirect. Scenario: expired access token, user opens `/login` → `getUser()` rotates the refresh token → redirect drops the new cookies → the next request presents a used refresh token. Fix: `for (const c of response.cookies.getAll()) redirect.cookies.set(c)`.

**M2. Hydration mismatch for Mac visitors on the deployed site.** `components/dashboard/topbar.tsx:96` renders `isMac() ? "⌘" : "Ctrl"` during SSR. Node 21+ exposes `navigator.platform`, so the dev machine renders `⌘` (I saw it in the `/demo` HTML) but Vercel's Linux box renders `Ctrl`; every Mac/iOS visitor to the statically prerendered `/demo` then gets a text mismatch and a client re-render. Fix: gate on `useMounted()` like `ThemeToggle` and `DemoBanner` already do.

**M3. Tags are validated in the schema but not at the input.** `index-card.tsx:122`, `bulk-bar.tsx:30`, `command-palette.tsx:63` accept any text; `addTag` (`provider.tsx:433`) only lowercases. In demo mode `applyPatch` → `bookmarkSchema.parse` throws inside `LocalRepository.mutate` (a throw, not a `Result`), so typing `c/c++` leaves the optimistic tag on screen, the write is lost, and an unhandled rejection is logged. In cloud mode it rolls back with the generic "Invalid change." Fix: run `tagSchema.safeParse` in `addTag` and show the rule from the schema message. Same gap for `renameTagAction` (`actions/bookmarks.ts:87`): an invalid `to` would be stored by the RPC and make every subsequent `rowToBookmark` throw, taking the dashboard down.

**M4. Shift+A select-all is dead.** `keyboard.tsx:52` checks `e.key === "a"` with `e.shiftKey`, but with Shift held `e.key` is `"A"`. Advertised in `help-sheet.tsx:15`. One-line fix (`e.key.toLowerCase()`). Also `move(index < 0 ? 1 : 1)` at `:38` is a no-op ternary, and the `t` shortcut listed in the card menu and help sheet (`index-card.tsx:78`, `help-sheet.tsx:13`) has no handler.

**M5. Undo of delete relies on index alignment.** `provider.tsx:410-414` zips `res.data.created[i]` with `targets[i]`. `SupabaseRepository.importBookmarks` dedupes through a `Map` and PostgREST does not guarantee returned-row order; if any target was re-added before Undo, `created` is shorter and `health`/`lastOpenedAt` land on the wrong cards. Fix: match by `urlNormalized`.

**M6. N parallel server actions for bulk operations.** `provider.tsx:368,394,565` fire one `updateBookmarkAction`/`deleteBookmarkAction` per card (up to 40 for a health check), each calling `revalidatePath`. Fix: add `updateManyAction`/`deleteManyAction` that hit Postgres once (`.in("id", ids)`).

**M7. False statement in test comment.** `lib/repo/contract.test.ts:7-8` says `SupabaseRepository` is "exercised against a real project in CI when credentials are present (see ci.yml)". `ci.yml` has no such job; `SupabaseRepository` has zero tests. Either add a mocked-client contract run (the plan called for it) or delete the sentence. A reviewer who checks this will distrust the other comments.

**M8. Accessibility gaps.** Cards (`index-card.tsx:191`) are clickable `<article tabIndex={-1}>` with no `role`, so Tab users cannot reach or open a card without knowing `j/k`. The list layout uses `role="table"`/`role="row"` without `cell` children (`bookmark-grid.tsx:43`, `index-card.tsx:161`), which is invalid ARIA. The mobile drawer (`shell.tsx:49-57`) is a hand-rolled overlay with no `role="dialog"`, focus trap or Escape handling while the other dialogs correctly use Radix. Fix: make the title a real `<a href>` with `onClick` interception, drop the table roles or complete them, and render the drawer in `DialogContent`.

**M9. Unbounded Gemini call.** `lib/enrich/gemini.ts:71` has no timeout; `safeFetch` has a 5 s budget but the model call can hold the function for the platform maximum. Pass `httpOptions: { timeout }` or wrap with `AbortSignal.timeout`.

### LOW

- **DB error text reaches the client.** `lib/repo/supabase.ts:150,161,168,185,206,220,227,237` return `error.message` (Postgres/PostgREST wording, constraint names) as the user-facing `INTERNAL` message. Log it, return a generic string.
- **Dead code / unused exports:** `searchBookmarksAction` (`actions/bookmarks.ts:91`, README says intentional but it is still an untested action), `pipelineFailure` (`pipeline.ts:98`), `highlightRanges` (`rank.ts:173`), `relativeTime` (`utils.ts:12`), `MenuLabel`/`shortcut` prop (`ui/menu.tsx:10,29`, call sites inline their own `<span class="kbd">` instead), `DialogTrigger`/`DialogClose`, `ExtractedPage.lang` (computed, never read), `RateLimitVerdict.remaining`. `health/route.ts:43` has `code === "BLOCKED_URL" ? "dead" : "dead"`. `provider.tsx:171` `describe(error)` is `error.message`. These are the lines that read as generated.
- **Duplicated logic:** two `decodeEntities` implementations (`extract.ts:62`, `netscape.ts:31`; the latter throws `RangeError` on `&#1114112;` and crashes the import), the demo storage key string repeated in `settings.tsx:102`, three copies of the `next` path check.
- **`IndexCard` is `memo`'d** (`index-card.tsx:23`) but reads `api`/`state` from context, so every provider update re-renders every card anyway; either pass only primitives or drop `memo`.
- **Zero component or route tests** despite `@testing-library/react`, `jest-dom`, `jsdom` and `@vitejs/plugin-react` in devDependencies and a `vitest.setup.ts` that imports jest-dom. The plan promised three.
- **`signUpAction` returns Supabase's raw `error.message`** (`auth.ts:42`), which enables account enumeration ("User already registered").
- **Body size:** route handlers parse any JSON body (a 2 MB payload was accepted and parsed before Zod rejected it). Check `content-length` or read with a cap.
- **DNS lookup is outside the abort budget** (`ssrf-guard.ts:205`); a slow resolver extends the 5 s promise.
- **`createCollection` position = `count`** (`supabase.ts:199-202`) races under concurrent creates; use `max(position)+1` in SQL or let the client reorder.
- **Marketing copy vs behaviour:** landing and README say "nothing leaves your browser" in demo mode, but every saved URL is sent to `/api/enrich` and on to Gemini.
- **`ExportDialog`** revokes the object URL synchronously after `click()` (`export-dialog.tsx:24`), which cancels the download in some Firefox versions; defer with `setTimeout`.
- **Migration nits:** `pg_trgm` should be installed `with schema extensions` on Supabase; both functions lack `set search_path = ''` (Supabase's advisor flags this); no index on `bookmarks.collection_id` for the `on delete set null` FK.

## 3. Done well (talk about these)

- **SSRF guard that holds up** (`lib/url/ssrf-guard.ts`): every IPv4 spelling, IPv6-mapped/NAT64/ULA/link-local ranges, DNS resolution with every address checked, manual redirects re-validated per hop, one abort budget for the whole exchange, streamed body with a byte cap, and an honest comment about the remaining DNS-rebinding window. Table-driven tests, including mocked redirect chains.
- **Repository boundary with a contract test.** `BookmarkRepository` + `LocalRepository` (reference) + `SupabaseRepository` + `RemoteRepository`, one test suite pinning dedupe, patch semantics and collection deletion. This is the cleanest interview story in the repo.
- **Postgres does the invariants.** Unique `(user_id, url_normalized)` with `23505` mapped to a typed `DUPLICATE`, RLS `using`/`with check` on every verb, generated weighted `tsvector` + GIN + trigram, `rename_tag` as one statement, `updated_at` trigger. Verified the migration applies cleanly.
- **The model is treated as untrusted input.** `responseSchema` on the request, Zod on the response, graceful `ai` → `metadata` → `none` degradation with the status surfaced on the card.
- **Errors as values.** `Result<T>` with a closed `ErrorCode` set and an `HTTP_STATUS` map, used consistently across actions, repos and routes; nothing throws across the client boundary.
- **Next 16 used correctly:** `proxy.ts` with the documented `getAll`/`setAll` cookie shape, `searchParams` awaited, `useActionState` forms, `force-dynamic` on authed pages, `agentRules` is a real 16.3+ option.
- **URL canonicalisation** (`lib/url/normalize.ts`) separates "what we open" from "what we dedupe on", strips tracking params, is idempotent and tested as such.
- **Engineering hygiene:** strict TS with no `any`, pinned deps, `.nvmrc`, `.env.example`, `npm run verify` mirrored exactly in CI, build passes with no secrets, Node-only modules documented as such.
